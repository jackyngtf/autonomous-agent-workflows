# 01 · 背景與個人角色

[English](01-context-and-role.md) · [繁體中文](01-context-and-role.zh-TW.md) · [專案概覽](../../README.zh-TW.md)

兩項定期報表工作，需要將營運系統的資料整理成人員既有的使用格式：每月一份 Excel 活頁簿。一項從每日 CSV 收集 PBX 通話紀錄，另一項透過 API 收集 NAS 檔案傳輸事件。兩者都需要判斷日期是否完整、目的地已涵蓋哪些資料、輸入是否有效，以及更新後的活頁簿能否安全發布。

我負責建立操作指引、Python 資料處理方式，以及報告與例外處理規則。工作也包括根據執行紀錄中的活頁簿缺陷、執行時間限制及環境故障，調整後續程序。

## 我的負責範圍

| 範疇 | 具體工作 |
|---|---|
| 工作流程設計 | 定義可處理的輸入、日期邊界、輸出結構及停止條件。 |
| 系統整合 | 連接既有 CSV／API 來源、活頁簿處理及 NAS 發布步驟。 |
| 資料完整性 | 建立重建前、上傳前及下載已發布檔案後的檢查。 |
| 日常維運 | 記錄執行結果與事件，將有用的發現整理成操作指引。 |
| 作品集 | 提供去識別化說明及可供檢視的合成資料離線示範。 |

專案使用既有 PBX／NAS 系統、Claude 執行工具及 Python 函式庫。我沒有開發底層語言模型或排程平台；產生通話 CSV 的接收器也是獨立元件。

## Agent 的角色

Agent 閱讀程序、檢視現況、呼叫確定性的資料處理程式，並處理例外。Python 負責解析、分組、重建與比較。排程負責啟動工作階段；Agent 的作用在於依據證據及書面邊界作出操作判斷。

當程序仍在演進、特殊故障需要調查時，這種安排有實際用途。已穩定的處理規則則應逐步整理成可重用函式及測試。單靠操作文件，無法強制執行所有安全條件。

作品集亦記錄 [eTMS 排程交接](07-etms-document-handoff.zh-TW.md)，由獨立 engine 負責檔案替換。入口指示建立預期範圍及人工控制模式。[2026 年 9 月 22 日的唯讀檢視](../evidence/etms-deployment-review-2026-09-22.zh-TW.md)已確認部署檔案及 shadow 設定，並檢查程式限制，沒有執行操作程式。另行評估的手動 shadow 報告記錄 30 項暫緩、零替換。這些紀錄與尚未部署的離線候選檢查，都不能證明 engine 的開發歸屬或成功的 live 替換。

## 本案例可以證明的範圍

現有資料包括具日期的報告、故障筆記、指引變更及恢復用輔助程式。它們支持特定的成功新增、停止執行及驗證改進案例，無法據此證明持續可用性、量化的人力節省或完全無人介入的恢復能力。

公開版本讓讀者了解設計，無須接觸原始營運紀錄或連接實際系統。[證據索引](../evidence/README.zh-TW.md)會區分歷史結果與目前的離線示範。
