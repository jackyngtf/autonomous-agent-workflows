# 03 · 完整性與驗證

[English](03-integrity-and-verification.md) · [繁體中文](03-integrity-and-verification.zh-TW.md) · [專案概覽](../../README.zh-TW.md)

關鍵問題是輸出是否包含預期紀錄，並保留既有資料。能成功開啟 XLSX，只回答了其中很小的一部分。

## 資料保留的約定

這些活頁簿存放結構化的營運表格。重建流程會建立包含既有紀錄與新增工作表的月報，再替換遠端檔案。「保留既有資料」指約定的表格內容；發布時，遠端活頁簿檔案本身會被替換。這並非對任意 Excel 圖形、公式、巨集或封裝位元組的完整保留承諾。

設計將檢查分成數個邊界：

| 邊界 | 需要確認的事項 |
|---|---|
| 輸入 | 預期欄位結構、有效紀錄、可處理日期，以及異常資料的明確處置 |
| 原始活頁簿 | 檔案可讀、工作表涵蓋範圍已知，並獨立取得數量及內容 |
| 重建活頁簿 | 名稱、順序、數量、日期與應保留的值符合預期 |
| 已發布版本 | 下載的輸出與預期活頁簿一致 |
| 來源清理 | 該份輸入所對應的發布檢查已通過 |

歷史版本的驗證深度不盡相同。上表是設計約定；各項證據會另外說明來源實際記錄了哪些檢查。

## 數量檢查也可能共享同一個錯誤

6 月 25 日，NAS 重建程序把舊標題列當成資料，再在上方寫入新標題。「原始」列數也由同一個錯誤假設推導，因此數量表面上一致。內容比較才發現重複標題及資料位移。

報告記錄的修正是略過原有標題列，並重新讀取原始活頁簿作為比較依據。驗證的預期值需要有足夠獨立性，才能挑戰轉換結果。報告也指出，問題修正前沒有上傳。詳見[執行案例摘要](../evidence/selected-run-extracts/README.zh-TW.md)的 **NAS-20260625**。

## 驗證深度必須配合說法

9 月 15 日的 NAS 輔助程式檢查所有工作表的列數，抽查兩筆既有資料，並檢查大部分新工作表的首末日期。只有較小的週末工作表進行完整日期掃描。因此，不能將結果寫成「逐格確認所有內容沒有改變」。

同樣地，工作表名稱一致，無法證明已發布檔案包含所有預期紀錄。可重用版本應明確比較約定範圍內的值、區分檔案不存在與讀取失敗，並在 API 批次可能截斷時停止。

公開離線示範使用合成資料，使驗證方式可供檢視。它與歷史部署是不同層次的證據；本機發布模擬也不能驗證實際 SMB 傳輸。
