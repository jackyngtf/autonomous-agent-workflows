# 證據使用說明

[English](README.md) · [繁體中文](README.zh-TW.md) · [專案概覽](../../README.zh-TW.md)

本目錄區分歷史報告、設計規則，以及讀者能在本機重現的行為。盤點日期為 **2026 年 9 月 22 日**；作品集檢視期間沒有連接正式系統。

[eTMS 案例](../case-study/07-etms-document-handoff.zh-TW.md) 的證據層次不同：已檢視入口指示，但未取得私有 engine、設定及操作結果。它不佔報告清單的任何一列，也沒有經驗證的換版次數或回復能力主張。

- [報告檔案清單](run-ledger.csv)：92 份主要執行報告、來源摘要值，以及明確標示的未知欄位。
- [執行紀錄章節](../case-study/05-operating-record.zh-TW.md)：本次盤點能支持的結果。

## 證據分類

| 分類 | 含義 |
|---|---|
| 設計規則 | 操作指引描述的預期邊界；是否被強制執行須另外評估。 |
| 報告記錄 | 具日期的報告記載該結果；本次沒有重新執行私人整合流程。 |
| 來源檢視 | 已檢視程式或文件中的可見行為，未必已實際執行。 |
| 離線重現 | 本機合成資料示範或測試，不能證明正式環境行為。 |
| 改善提案 | 未來改善，並非現有能力。 |
| 尚未釐清 | 現有來源互相矛盾或不足以判斷。 |

## 清單範圍與欄位

只計算各流程主要 `reports/` 每月目錄中的 `avaya_call_log_report_*.md` 與 `nas_access_log_report_*.md`。排除封存副本、知識整理及自我改善報告，共有 **47 份 Avaya 檔案、46 個日期**，以及 **45 份 NAS 檔案、45 個日期**。

| 欄位 | 解讀方式 |
|---|---|
| `artifact_id` | 穩定的清單標籤，不是排程執行識別碼。 |
| `workflow`、`report_date`、`source_report` | 流程、檔名日期及私人來源檔名。 |
| `execution_mode`、`reported_outcome` | 只為選定案例評估；其他列使用 `unknown`。 |
| `assessment_scope` | `selected_narrative` 表示已選作案例；`inventory_only` 表示僅盤點。 |
| `reported_new_sheets`、`reported_new_data_rows` | 選定報告的新增量；留空表示未評估，不是零。 |
| `validation_scope`、`intervention`、`provenance_notes` | 保守註解，包括恢復方式及來源不明的更新。 |
| `source_sha256` | 盤點時私人報告位元組的 SHA-256 摘要值。 |
| `inventory_date` | 建立盤點的日期。 |

多數列刻意僅作檔案盤點，避免由檔名或一般完成字句推斷成功。Avaya 在 9 月 11 日的兩份報告分開列出。已知受阻的工作階段記為零新增；尚未評估的報告則留空新增欄位。

SHA-256 摘要值方便擁有人日後核對來源快照，不能證實報告內容，也不提供私人原文的公開存取權。來源定位資訊只使用流程名稱、日期、檔名及行號；原始報告、識別資料、基礎設施細節及營運紀錄均未公開。

## 公開敘事保留的限制

原始報告集合不是完整的執行歷史。9 月檢查發現目的地已有更新，但本機沒有對應的來源紀錄。部分報告對內容驗證的說法過強，或與後續發現矛盾。案例摘要會縮窄相關說法，不把單份報告當成確定證明。

檔案總數及報告新增量都不能提供可用性的計算分母。本清單不推導成功率、人力節省、投資回報、全面資料保留或持續運作等說法。
