# Avaya 通話紀錄流程：程序參考

[English](WORKINSTRUCTION.md) · [**繁體中文**](WORKINSTRUCTION.zh-TW.md)

> 重新編寫的設計參考，不是可執行的正式操作手冊。不包含真實連線細節或憑證。歷史實作的驗證深度不一；下列檢查區分預期約定與部署仍需完成的工作。

## 用途與資料約定

流程讀取 PBX 接收器產生的每日 SMDR CSV，規劃月報內缺漏的日期。原排程為平日 10:00。日期資格以 `Australia/Melbourne` 計算，包含夏令時間，並排除目前本地日期。

公開 [SMDR 測試資料](../../sample-data/smdr-receiver/output/smdr_2026-08-04.csv)及[示範解析器](../../demo/workflows.py)定義了 30 欄約定。這是本範例的資料結構，不代表所有 PBX 設定都產生相同紀錄。使用來源前，應驗證標題、每列欄數及日期。

工作簿約定是已知工作表名稱及欄位的表格文字資料。任意公式、巨集、繪圖及其他 Excel 功能，不屬於這次重建範圍。

## 程序與停止條件

| 步驟 | 操作 | 必要決策或檢查 |
|---|---|---|
| 1. 檢查 | 確認截止日期、來源清單及目前目的地 | 驗證、存取或解析失敗，不等於檔案不存在 |
| 2. 規劃 | 找出合資格而未收錄的日期 | 不應無聲地向既有日期加入重複或改動紀錄 |
| 3. 解析 | 按明確結構驗證全部來源 | 格式錯誤或欄數混雜，應阻止受影響更新 |
| 4. 準備 | 記錄既有資料快照並建立待驗證工作簿 | 預期紀錄不能只由重建結果推導 |
| 5. 驗證 | 比較工作表名稱、列數及預期儲存格值 | 發佈前偵測紀錄變動及重複標題列 |
| 6. 發佈 | 正式連接模組寫入已核准檔案 | 另外定義並行、備份及部分上傳恢復方法 |
| 7. 取回 | 下載並驗證已發佈副本 | 驗證失敗會阻止來源清理，並需報告發佈事件 |
| 8. 報告 | 記錄結果、驗證範圍及清理判斷 | 正式清理前，需確認每個來源與目的地紀錄相符 |

重建可能替換工作簿檔案。「保留」指支援範圍內的既有紀錄，不代表檔案未變或 XLSX 封裝位元組完全相同。

來源紀錄在預期目的地通過驗證後，該檔案才可以成為清理候選。公開示範只報告資格，不會刪除。格式錯誤與不確定情況會保留，供操作負責人檢查。

## 正式部署需要補充

- 來源及目的地設定、服務權限、安全的憑證提供方式。
- 實際 PBX 資料結構，以及衝突或已收錄日期的處理政策。
- 已定義並行、備份及恢復行為的發佈方法。
- 清理政策、保留期間及事件升級負責人。
- 依賴版本及明確支援的工作簿約定。

文字指引不能代替這些控制。某個環境的 SMB 或接收器觀察，應先驗證才套用到其他環境。

## 執行本機重建示範

```sh
python -m demo --workflow avaya --output-dir output/demo
```

示範使用合成檔案、驗證本機產出，並產生執行報告及機器可讀證據。它不測試 SMB 傳送、排程器或正式刪除。詳見[指南](../../demo/README.zh-TW.md)及[合成報告格式](sample-report.zh-TW.md)。
