# eTMS 替換：交接程序參考

[English](WORKINSTRUCTION.md) · [**繁體中文**](WORKINSTRUCTION.zh-TW.md)

本文按現有入口 skill 重建其描述的交接流程。已部署的 engine 及 driver 不在公開 repository 內。本案例沒有以 engine 原始碼、測試或執行報告作為已檢視證據，因此下列步驟是要求，不是實際觀察到的執行結果。

## 輸入與部署邊界

任務預期有一個待更新文件資料夾，以及可從獲授權外部儲存位置取得的部署 engine 套件。套件提供 driver 及設定。由靜態 SQL 快照產生的 manifest，是 engine 使用的檔案輸入；任務仍禁止連接資料庫或執行 SQL。

指引指定平日 09:30 執行，未列明時區。部署負責人需要確認排程及存取細節。本公開參考省略主機、帳戶、憑證、共享位置及內部檔案系統路徑。

## 交接次序

| 步驟 | 約定 | 失敗或不確定時 |
|---|---|---|
| 1. 取得部署套件 | 經授權存取取得預期 engine、driver 及設定 | 缺少必要檔案時報告「ENGINE NOT DEPLOYED」並停止 |
| 2. 遵守設定 | 使用設定的 shadow 或 live 模式，不修改模式 | 不自行推定可以啟用 live |
| 3. 呼叫 driver | 將規劃、驗證及獲准替換交予預先建立的實作 | 報告當機及最後已知狀態，不手動替換 |
| 4. 檢查結果 | 閱讀結構化輸出及最新報告 | 保留部分完成、失敗及未明狀態，不虛構成功 |
| 5. 報告處理情況 | 解釋已規劃、已替換及暫緩輸入、原因與後續行動 | 含糊情況下停止；不在未報告前重試失敗的 live 寫入 |

## 模式與可執行變更

**Shadow：**約定要求只規劃及驗證，正式環境零寫入。在操作負責人修改設定前，這是指引指定的模式。現有入口檔案不能確認目前實際部署模式。

**Live：**driver 只可執行 engine 計劃內的檔案替換，以及約定授權的相關封存、日誌及報告寫入。Engine 負責替換及要求的回復行為。本次未驗證原子性、回復可靠性或任何成功的正式結果。

Agent 不得以手動複製檔案或修改資料庫參照，補救 driver 失敗。資料庫版本欄位、培訓紀錄、進度、完成紀錄、指派、測驗、應用程式碼及容器設定，均不屬於範圍。文件檔案替換，不應被描述為更新了這些紀錄。

## 報告約定

私人操作報告應記錄：

- 設定模式及 driver 結果，包括當機或部分完成狀態。
- 每個輸入回報的 `PLANNED`、`SWAPPED` 或 `HELD` 處理狀態及原因。
- 提交團隊或操作負責人需要解決的事項。
- 未通過預期可用性檢查的 manifest 目的地，以及 engine 錯誤。
- Live 模式下，回報的已替換檔案及相應封存檔名。
- 任何回復嘗試及回報狀態，不以沒有訊息推定成功。

這些是預期欄位，不是虛構的執行範例。私人報告可能需要內部檔案識別資訊；如要公開作為證據，需另外整理及去識別。

## 支持更強說法所需的證據

要驗證規劃、檔案限制及回復，需要檢視 engine、設定證據、受控 shadow 輸出及失敗測試。要聲稱完成正式替換，還需要獲授權的執行紀錄及前後證據。在此之前，本案例展示的是具明確限制的排程交接設計。
