# eTMS 文件替換：排程交接流程

[English](README.md) · [**繁體中文**](README.zh-TW.md)

第三個流程將文件替換交由另外部署的 engine 處理。現有入口指引指定於**平日 09:30** 無人值守執行：檢查待更新文件資料夾，從外部儲存位置取得已部署的 engine 及 driver，按設定模式執行，然後解釋結果。

來源沒有指定排程時區。**2026 年 9 月 22 日**開始檢視時，設定為 shadow，手動執行將 30 項輸入全部暫緩。修正通過測試並獲授權切換 live 後，**9 月 23 日**報告記錄 19 SWAPPED、8 HELD，並有唯讀檔案及 HTTP 檢查支持。[附日期檢視](../../docs/evidence/etms-deployment-review-2026-09-22.zh-TW.md)區分各個階段，亦記錄餘下封存標籤缺陷及證據限制。

## Agent 的責任

Agent 檢查必要部署檔案是否存在，在授權設定內呼叫 driver，並閱讀 driver 的 JSON 輸出及報告。報告應說明哪些輸入已規劃、已替換或暫緩、暫緩原因，以及需要處理的事項。

Agent 不得臨時手動替換檔案、連接資料庫、執行 SQL、更改培訓紀錄，或自行從 shadow 切換至 live。變更限於 engine 計劃內的檔案，以及指定封存、日誌及報告，並須經 engine 或 driver 執行。

## 交由其他部分負責的行為

| 項目 | 證據邊界 |
|---|---|
| Shadow 模式 | 9 月 22 日快照設定為 shadow。程式跳過正式文件替換，但仍處理收件區清理及上傳報告。 |
| Live 模式 | 由操作負責人透過設定選擇；9 月 23 日獲授權切換後，觀察到本次 live 結果。 |
| 替換與回復 | 交由 engine 負責。唯讀檢查支持一次發布結果；備份是否完全保留執行前內容及回復安全性仍未驗證。 |
| Manifest | 約定提及由靜態 SQL 快照產生的檔案清單；不代表允許連接資料庫或執行 SQL |
| 結果報告 | Driver 回傳零不代表 engine 成功；須獨立核對報告、逐項狀態及遠端結果。 |
