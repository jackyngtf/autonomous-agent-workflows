# eTMS 文件替換：排程交接流程

[English](README.md) · [**繁體中文**](README.zh-TW.md)

第三個流程將文件替換交由另外部署的 engine 處理。現有入口指引指定於**平日 09:30** 無人值守執行：檢查待更新文件資料夾，從外部儲存位置取得已部署的 engine 及 driver，按設定模式執行，然後解釋結果。

來源沒有指定排程時區。**2026 年 9 月 22 日**的唯讀檢查已確認部署位置有 driver、engine 及設定檔，快照中的模式為 **shadow**。檢視閱讀了原始碼，沒有執行操作程式。另行評估的使用者手動 shadow 報告記錄 30 HELD、0 PLANNED、0 SWAPPED。這是實際觀察到的暫緩結果，不是成功替換或排程觸發成功。

## Agent 的責任

Agent 檢查必要部署檔案是否存在，在授權設定內呼叫 driver，並閱讀 driver 的 JSON 輸出及報告。報告應說明哪些輸入已規劃、已替換或暫緩、暫緩原因，以及需要處理的事項。

Agent 不得臨時手動替換檔案、連接資料庫、執行 SQL、更改培訓紀錄，或自行從 shadow 切換至 live。變更限於 engine 計劃內的檔案，以及指定封存、日誌及報告，並須經 engine 或 driver 執行。

## 交由其他部分負責的行為

| 項目 | 證據邊界 |
|---|---|
| Shadow 模式 | 快照設定為 shadow。程式會跳過正式文件替換，但仍處理收件區清理及上傳報告，並非完全沒有遠端變更。 |
| Live 模式 | 由負責操作人員透過設定選擇，不由排程 agent 決定；本文不聲稱已取得正式執行結果。 |
| 替換與回復 | 交由 engine 負責。靜態檢視不能證明替換、回復或失敗恢復成功。 |
| Manifest | 約定提及由靜態 SQL 快照產生的檔案清單；不代表允許連接資料庫或執行 SQL |
| 結果報告 | Driver 不傳遞首次 engine 子程序狀態，並在 shadow 回傳零結束碼。是否完成及逐項結果需要另行核對；本文不聲稱已完成正式執行。 |
